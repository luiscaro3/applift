# Scope and evidence

Draft 0.1, 21 October 2026. A specification kit with zero runtime code or package dependencies.

## Available

- Four contracts: identity/session recovery, personal/shared ownership, subscriptions/access and management-screen mapping.
- Logical relationship diagrams, workflow-local field guidance and conditional recovery information.
- A short bridge-plan template and one worked example that combines the initial contracts.
- Standing agent instructions preserving native architecture and limiting additions to demonstrated gaps.
- MIT license and the supplied AppLift logo.

The docs are intended to save host-mapping decisions rather than replace provider SDK instructions. No mandatory schema, Store interface, role system, ORM or code generator is supplied.

## Evidence and limits

Author review checked field authority, relationship/workflow consistency, optional storage and recovery paths. Relative documentation links and image references were checked locally. The worked example is hypothetical and was not executed. Mermaid source is supplied; a successful rendering test is not claimed.

An independent fresh-context adoption trial has not been completed. There are no measured time/token savings, universal compatibility or production-readiness claims. Real provider acceptance is separate from reviewing or using these contracts.

## Next useful check

Use this kit and a frozen, isolated host snapshot to plan the smallest missing portion of paid multi-user access. Record mappings saved, unresolved choices, needless new entities and manual rescue. Use only the public kit and host source; a same-author example does not count as independent evidence.

Success is a bounded plan preserving native IDs and guards, naming operator decisions, covering ordinary recovery and avoiding unnecessary storage/runtime. Fix observed gaps; stop before a broad benchmark or provider certification program.

## Conditional scope

External-service OAuth connection/reconnection and reliable external effects need separate specs only when a concrete app requires them. Sign-in session recovery and billing recovery are already covered. Uploads, marketplaces, enterprise access systems and additional provider wrappers are not implied by the initial scope.
